# 分叙 StoryBranch

AI 分支叙事创作引擎 —— 面向互动小说与游戏叙事创作者的分支故事创作工具。

设定角色与世界观，AI 生成场景与分支选项；每一次选择都是一条新支线，随时回溯到任意一幕，换个选择长出新的剧情。右侧路径面板记录你探索过的整棵故事树，阅读模式提供当前路径的沉浸式阅读体验。

## 它解决什么问题

分支叙事创作的核心痛点：**每增加一个分支点，创作与维护成本成倍增长**——多条故事线要保持角色一致、世界观自洽、节奏可控，创作者往往写了两三条线就力不从心。

StoryBranch 把这件事交给 AI：它负责根据已发生的剧情续写场景、生成走向差异明显的选项，并在 Prompt 中持续注入角色设定与剧情历史以维持一致性。创作者只做最擅长的事——**判断与选择**。

## 核心用户路径（可完整体验）

1. 首页设定故事类型 / 主角 / 世界观
2. AI 生成开场场景 + 3 个分支选项
3. 点击选项 → AI 结合全部前文续写下一幕
4. 回溯：点击「回到此幕，换个选择」或右侧路径面板任意节点 → 选择不同分支，剧情走向另一条线
5. 路径面板实时呈现已探索的故事树（未走路径为灰色，当前路径高亮）
6. 阅读模式：连贯阅读当前路径的完整故事

## 技术栈

- **Next.js 14**（App Router）+ TypeScript + Tailwind CSS
- **AI**：任意 OpenAI 兼容接口（本项目使用阿里云百炼 qwen3.7-plus），服务端 API Route 代理调用，Key 不落前端
- **存储**：localStorage（无需数据库/注册），路径树用节点图数据结构表示
- **部署**：Vercel（或任何 Node 环境）

## 运行

```bash
npm install
cp .env.example .env.local   # 填入你的 AI_API_KEY（不填则进入演示模式）
npm run dev                  # http://localhost:3000
```

### 环境变量

| 变量 | 说明 | 默认 |
|------|------|------|
| `AI_BASE_URL` | OpenAI 兼容接口地址 | `https://api.deepseek.com` |
| `AI_API_KEY` | API Key。**不配置则自动进入演示模式** | 空 |
| `AI_MODEL` | 模型名 | `deepseek-chat` |

本项目实际使用的配置（阿里云百炼 Qwen）：

```bash
AI_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
AI_API_KEY=<你的百炼 Key>
AI_MODEL=qwen3.7-plus
```

### 部署到 Vercel

1. 把仓库推到 GitHub
2. [vercel.com](https://vercel.com) 导入仓库
3. 在 Project Settings → Environment Variables 中填入 `AI_API_KEY`（及可选的 `AI_BASE_URL` / `AI_MODEL`）
4. Deploy

## 完成边界（诚实声明）

**真实可用**
- 完整核心路径：设定 → AI 生成 → 选择 → 分支回溯 → 路径面板 → 阅读模式
- AI 实时生成（配置 Key 后）：Prompt 注入角色设定 + 完整剧情历史，JSON 结构化输出，含超时 / 格式异常 / 网络错误的处理与重试
- localStorage 持久化，多故事管理（继续 / 删除）

**简化处理**
- 路径可视化采用缩进列表而非图形化树
- 演示模式（未配置 Key 时）：内容为按类型预置的手写模板，交互流程与真实模式完全一致，界面明确标注
- 无用户系统 / 云端同步（本地存储对验证核心路径已足够）

**未完成（后续优先级）**
1. 图形化故事树（react-flow）与分支对比视图
2. 「换一批选项」与单幕重写
3. 长故事的上下文压缩（当前直接拼接全部历史，超长剧情需摘要）
4. 导出 Markdown / 分享只读链接

## 开发中 AI 的参与

本项目由 AI 结对开发完成：需求梳理与范围收敛、数据结构（节点图）设计、全部代码实现、边界情况（JSON 解析容错、双击防抖、回溯后重生成）均由 AI 主导，人工负责产品判断与验收。
